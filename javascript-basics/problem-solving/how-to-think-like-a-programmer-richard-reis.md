# How to Think Like a Programmer

**Source:** [freeCodeCamp — How to Think Like a Programmer](https://www.freecodecamp.org/news/how-to-think-like-a-programmer-lessons-in-problem-solving-d1d8bf1de7d2/)

## Core Idea

Programming is not mainly about memorizing syntax. It is about **solving problems**.

> “The biggest mistake I see new programmers make is focusing on learning syntax instead of learning how to solve problems.”

---

## Problem-Solving Process

### 1. Understand the Problem

Before coding, make sure you actually understand what is being asked.

Ask:

- What is the input?
- What should the output be?
- What are the rules?
- Can I explain it in plain English?

> “If you can’t explain something in simple terms, you don’t understand it.”

### 2. Plan Before Coding

Don't immediately open the editor.

First describe the steps:

```text
Input → Steps → Output
```

Then turn those steps into code.

### 3. Break It Down

Big problems become easier when divided into smaller problems.

> “Do not try to solve one big problem. You will cry.”

If you cannot solve the original problem, make a **smaller version** that you can solve.

Then gradually build back up.

### 4. When You're Stuck

Don't panic. Use this sequence:

```text
Debug → Reassess → Research
```

**Debug:** Find where reality differs from what you expected.

> “The art of debugging is figuring out what you really told your program to do rather than what you thought you told it to do.”

**Reassess:** Step back and try a different approach.

**Research:** Search for the specific concept or sub-problem—not the entire solution.

---

## Main Pain Points

| Pain Point | Better Habit |
|---|---|
| Coding immediately | Understand first |
| No idea where to start | Break it down |
| Randomly changing code | Debug systematically |
| Getting frustrated | Become curious |
| Copying solutions | Research specific concepts |
| Problems feel too hard | Make them smaller |
| Expecting instant improvement | Practice repeatedly |

---

## Most Important Lesson

When you think:

> **“I don't know how to solve this.”**

Ask:

> **“What smaller version of this problem can I solve?”**

That is the heart of programming problem-solving.

---

## Quotes to Remember

> “Do not try to solve one big problem. You will cry.”

> “Reduce the problem to the point where you know how to solve it and write the solution.”

> “The best programmers/problem-solvers are more curious about bugs/errors than irritated.”

> “If you want to be a good problem-solver, solve a lot of problems!”

---

## Simple Rule

```text
Understand
   ↓
Plan
   ↓
Break it down
   ↓
Solve
   ↓
Debug
   ↓
Research if needed
   ↓
Practice
```

**Don't rush to the solution. Train yourself to find the solution.**
